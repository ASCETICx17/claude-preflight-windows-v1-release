# DNS 与 WebRTC 泄露检测

本功能在本机运行，不需要 API Key、付费订阅或注册账号。DNS / WebRTC 的执行只要求保存的本机代理填写正确且端口可用；TUN、固定出口和防火墙核验失败均不阻止测量。v7 起，未知、异常与超时仅作黄色提醒，不阻止 Claude 启动。

界面统一为“检测 DNS / WebRTC”，旧命令 ObserveNetwork 保留兼容。此操作不启动 Claude、不改白名单，不能替代完整启动检查。检测服务会看到实际路径，其中可能包括校园网出口；仅打开 HTTP 代理不代表 DNS / UDP 已被接管。

## 首次使用

1. 在个人配置页填写代理、固定出口、TUN、时区与语言，保存。
2. 打开“DNS / WebRTC”，点击执行检测。
3. 工具核对报告中的固定 HTTP 出口，同时将有效 DNS 观测自动填入空白或误填为代理 IP 的基线草稿。出口不匹配仍可填草稿，但保留出口异常提醒。
4. 基线可留空，也可保存作为以后比较的依据。不需要手动收集地址；最多采用 32 个精确 IPv4 / IPv6。保存不代表地址已验证安全。
5. 已有自定义基线不会被后台替换；显式点击“填入本次 DNS 地址”可更新草稿，仍需保存。没有有效报告或没有解析器地址时不能编造草稿；界面会明确说明原因。

这里记录的是递归解析器向权威 DNS 发请求时的出口。它常常不同于代理公网出口，也不同于客户端填写的 1.1.1.1 / 8.8.8.8 等 Anycast 接入地址。服务商的出口池变化时，需要重新核对允许列表。工具不会把首次观测自动当作可信基线。

通俗理解：固定出口是“网站看到你从哪里来”，DNS 列表是“本轮哪些服务器替你查了域名”。可以有多个实测 DNS 地址；取得有效报告后自动填入首次草稿，核对后保存，不必逐个复制，也不必等于固定 IP。把地址贴到 IP 查询网站看运营商 / ASN，再与代理中选择的 DNS 服务商核对；学校或本地运营商的地址应先排查，不应为了通过而直接加入。

这个字段只是检测结果的比较基线，不授予服务器权限，也不会改变实际 DNS 配置。自动填写的是未保存草稿，不是自动信任检测结果。保存的精确地址仅作变化比较；公共 DNS 地址池轮换会提示变化，不能仅凭变化判定泄露。远端 DNS 服务器可以用 IPv6 访问权威服务器，即使本机只使用 IPv4。

WebRTC 可以收集多个地址，但当前规则只允许保存的固定公网 IPv4；不同公网地址或公网 IPv6 显示黄色异常提醒，需核实来源；不会仅凭地理位置判为安全。局域网 / 本机名称和中继服务器地址不当作客户端公网出口。

原始时间 2026-10-22T04:40:54.9124480Z 是 UTC；UTC+8 对应 2026-10-22 12:40:54。界面现在显示本机时间和时区偏移，不再展示长串原始时间。STUN 是让检测服务器回答“它看到你的 UDP 来源地址是什么”；mDNS 是本地名称隐藏机制，TURN 是服务器转发，两者不当作你的公网出口。

## DNS 流程

HTTP 控制请求通过已配置的回环代理：

- 从 https://bash.ws/id 获取本次测试 ID。
- 六个 PowerShell runspace 并发调用 Resolve-DnsName，限定 A / DnsOnly / NoHostsFile，使用约 30 秒总预算的剩余部分并预留 4 秒取报告，保留 Windows 自己的服务器选择和 DNS 策略，不指定公共 DNS 代替系统测试。系统已返回错误时提前结束；记录实际等待与本阶段上限。
- 若返回 198.18/15 Fake-IP，仅在 Windows 实际选路指向在线虚拟网卡时，通过短 TCP 连接触发延迟上游解析；不依赖 v2rayN 配置路径或开关文件，不发送 HTTP 数据、账号或凭据。
- 经代理读取 https://bash.ws/dnsleak/test/{id}?json 的权威侧观测。
- 区分有效报告、error 错误对象、JSON 损坏和格式变化。查询已返回而服务未生成报告时等待 300 毫秒，最多重读一次；每次会话或报告请求最多 10 秒且受剩余总预算约束；报告传输超时也最多重读一次。系统查询没有返回时不反复请求空报告。
- 核对控制出口与完整白名单，逐一检查观测解析器是否在允许列表中。

服务不可达、无有效观测或未设允许列表均为未知；解析器地址池变化显示黄色提醒，不单独认定泄露。本地 Fake-IP 返回本身不作为无泄露证据，也不直接采用服务的结论文本。

界面分别显示获取会话、校验会话、系统 DNS 查询、报告下载、JSON 解析和结构校验的结果。HTTP 状态不是 200、网络超时、TLS 失败、返回网页、无效 JSON 与有效空报告不再合并成同一条“服务不可达”。成功响应也不等于通过：仍需核对 HTTP 控制出口与解析器允许列表。HTTP 客户端始终使用保存的代理，不自动直连、不跟随未核实的跳转、不关闭证书验证。

本项测量 Windows 默认解析链。浏览器独立 DoH、不同域名的分流和其他应用解析策略需分别验证；DNS 服务器国家与出口国家不同，不会自动被判定为泄露。

协议对接参考 [macvk/dnsleaktest v1.4](https://github.com/macvk/dnsleaktest/tree/v1.4)，服务页面为 [bash.ws DNS leak test](https://bash.ws/dnsleak)。PowerShell 客户端在本项目中实现，未捆绑或执行下载的第三方脚本。

## WebRTC 流程

使用已安装、签名核验通过的 Microsoft Edge：

- 独立临时资料目录、无头模式及 InPrivate，不读取日常浏览器账号。
- 加载本项目本地 HTML / JS，无远程脚本、广告或网页存储。
- 通过只绑定本机的临时调试通道回传浏览器结果；通道显式绕过系统代理。
- 由 RTCPeerConnection 和数据通道收集 ICE，不申请摄像头或麦克风权限。
- 分别检查 Cloudflare 与 Google STUN；浏览器启动、页面加载和 ICE 共用约 30 秒总预算的剩余时间，不再固定截在初次 16 秒。
- 先通过保存的代理请求 Google DoH，只查询这两个公开 STUN 主机名的 A 记录。校验问题名称、状态和公网 IPv4，最多使用每节点两个地址；失败时回到原 STUN 域名。两个解析请求并发、最多 5 秒。
- 保留原 STUN 域名（含原有 IPv6 能力），同时增加验证后的 IPv4 备用地址及原节点身份；UDP 按本机实际网络发出，不强制隐藏非代理流量。
- 两节点首次并发收集使用剩余预算。如果一节点有反射结果、另一节点没有且仍有时间，待初次连接关闭后，为缺失节点新建连接单独复测一次，最多 3 秒，不能突破总截止时间。首次候选和错误保留，不能用复测掩盖曾出现的额外公网地址。
- 主动关闭专用浏览器，Windows Job Object 管理其进程；正常退出删除自建临时目录，清理不完整显示黄色提醒。

不会为了得到“通过”而强制关闭非代理 UDP。两个 STUN 均须给出符合固定出口的公网反射地址；额外可见公网候选或未经允许的公网 IPv6 显示黄色提醒；文案按实测地址区分 IPv4 / IPv6，不再写“可能含 IPv6”。

LAN、Tailscale CGNAT、ULA、链路本地地址与 mDNS 名称不当作公网出口；TURN relay 属于中继服务器，不当作客户端出口。无响应、无有效候选或两节点覆盖不足均为未知。

每处 STUN 会显示候选收集是否完成、是否达到本轮时限、错误码和公网反射地址数量。“候选收集完成”不等于所有 STUN 请求都成功；错误码也可能与另一条接口上成功返回的候选同时存在，不应仅按错误码判定泄露。

### 为什么浏览器网站绿色，而这里显示未知？

网站上的“远程 IP”来自 HTTP 请求，不等于 WebRTC 收集到的 IP。当 WebRTC 的本地 / 公网地址都是空，网站可能显示“无泄露”，其含义是该网页本轮没有观察到地址暴露。本工具另外要求两个 STUN 证明固定出口，因此显示“本轮未观察到公网地址暴露；也未验证到两处 STUN 的代理出口”，保持未知，显示黄色提醒。没有因此确认泄露，也没有因此证明路径正确。

日常浏览器可能使用自己的安全 DNS、扩展和 WebRTC 策略；本工具测量 Windows 默认 DNS 和全新临时 Edge，不继承日常资料目录。两者测试路径和判定条件不同。临时 Edge 的异常不能直接当作 Claude 进程已经泄露的证据；Claude 仍须独立核验程序规则和实际流量。

此项测量独立 Edge 在当前 TUN 与代理参数下的浏览器环境。它没有注入 Claude、读取 Claude 内部状态，也不代表任意应用或所有媒体授权场景具有相同结果。

实现：LeakChecks.ps1、probes/BrowserProbe.cs、probes/webrtc.html、probes/webrtc.js。STUN 参考 [Cloudflare 文档](https://developers.cloudflare.com/realtime/turn/) 与 [WebRTC 官方示例](https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/)。

STUN 名称解析使用 [Google DoH JSON API](https://developers.google.com/speed/public-dns/docs/doh/json)，没有 API Key，不通过该 API 测量系统 DNS 泄露，也不发送用户访问过的域名。此步骤解决名称解析阻塞；节点或校园网不允许 UDP 时，仍可能没有 STUN 响应，保持未知。

DNS 与浏览器探针在两个 PowerShell runspace 同时开始，与出口 HTTP 和本地 TUN / 程序 / 防火墙核验重叠；各自保留超时和未知结果，单项失败不吞掉另一项。独立检测不加载完整防火墙核验。未用缓存通过结论替代本轮采样。


## 后台等待与启动分离

WPF 界面通过 LeakAdvisoryUI.ps1 持有两项 runspace。基础检查进程只执行 10 项必要条件，不创建或等待 DNS / WebRTC；探针在旁路后台运行，分别完成、分别更新。两项各约 30 秒总预算，到期显示未知并异步取消，窗口继续可用。关闭窗口会结束这些探针。

同一配置的检查或启动复用尚未完成的探针，避免重复请求。修改代理、固定 IP 或其他必要配置会取消旧任务并清除旧结果；晚到结果不会写入新配置。异常显示黄色并保留地址，绝不改成“无泄露”。

DNS 自动草稿只影响保存状态，不改变必要检查结论，不禁用已允许的启动。未保存时使用原有配置。必要字段的未保存修改仍禁用启动。已保存 DNS 基线只用于提示变化，不再是连接门槛。

## 状态与数据

| 状态 | 启动行为 |
|---|---|
| 本次未发现异常 | 继续核对其他必要项 |
| 发现异常 | 黄色提醒，不阻止启动或自动关闭 Claude |
| 无法确认 / 尚未配置 / 不完整 | 黄色提醒，不阻止启动 |

允许列表只保存在同一个 settings.json；观测地址和结果只在工作进程与界面内存中，不生成自动报告或白名单缓存。浏览器自身在系统 Temp 创建临时资料目录，正常结束清理；强杀或断电可有残留。公开导出器排除个人配置，并扫描当前 DNS 允许值是否散落到其他文本。

界面提供 DNS 来源与 WebRTC 人工复核网站链接。它们由用户点击才打开。
